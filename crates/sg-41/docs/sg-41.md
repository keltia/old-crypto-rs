# Schlüsselgerät 41 (SG-41): technical specification and validation plan

**Status:** Step 3 — typed wheel/pin foundations available; no cipher or stepping implementation is claimed.

**Scope:** 26-letter SG-41 (*Hitlermühle*), not the ten-digit SG-41Z.

## Machine and key model

The device is mechanical, without electrical rotors. Its six permanently installed pin-wheels have lengths **25, 25, 23, 23, 24, 24**, a total of **144 independently settable pins**. Each pin is inactive (`0`, left) or active (`1`, right). The complete set of pin bits forms the *internal/daily key*. The six wheel-window positions form the *external/message key*.

| Wheel | Length | Window markings | Cage contribution |
|---|---:|---|---:|
| 1 | 25 | `ABCDEFGHIKLMNOPQRSTUVWXYZ` | 1 |
| 2 | 25 | `ABCDEFGHIKLMNOPQRSTUVWXYZ` | 2 |
| 3 | 23 | `ABCDEFGHIKLMNOPQRSTUVWX` | 4 |
| 4 | 23 | `ABCDEFGHIKLMNOPQRSTUVWX` | 8 |
| 5 | 24 | `01`–`24` | 10 |
| 6 | 24 | `00 02 05 07 10 12 15 17 20 22 25 27 30 32 35 37 40 42 45 47 50 52 55 57` | inversion |

*Verify the alphabet lists above against Table 1 before using them as program constants.* In particular the physical alphabet omits J from wheel labels 1–4. The rotor/window coordinate and the pin-array index must not be conflated.

### Input/output alphabet and print head

- Keyboard has 26 letter keys; `J` serves as a **space** in the plaintext layer, and a literal plaintext J is conventionally written I.
- The machine prints plaintext and ciphertext on separate tapes; ciphertext is grouped by five.
- Four fixed scrambled letter rings are mounted on one print-head cylinder. The two outer rings are identical; the two inner rings are identical and in reverse order. The V/E control shifts the print-head alignment between encrypt/decrypt modes. **Do not implement this as a naive A–Z Caesar shift.**
- Table 2 (paper p. 12) is the authoritative 26-contact ring order. The two distinct ring sequences are transcribed in [the Step 2 fixtures](fixtures/sg41-reference.yaml) and checked for permutation integrity.
- Table 3 provides a local check: with PRN 8, encrypting `V` gives `I`; decrypting `I` gives `V` with the same state. This confirms direction and indexing, but is **not** a full implementation test.

## Cage / pseudo-random number

The SG-41 uses a **25-bar cage**, whose fixed lugs represent five weighted groups of bars: **1, 2, 4, 8, 10** for wheels 1–5. The sixth wheel participates in complementary/inversion selection. A bar can lock in three mechanical positions, but only its middle position engages the print-head gear. The net PRN is a number in `0..=25`.

At a conceptual level, for sensed wheel bits `b1..b6`, let `v = b1 + 2*b2 + 4*b3 + 8*b4 + 10*b5`. Wheel 6 toggles between direct selection and its complement, i.e. `v` or `25-v`, respectively. **Implementation must confirm polarity and timing using the exact cage diagrams (pp. 19–21) and published vector, rather than assuming this expression alone captures the complete machine.**

Importantly, the cage uses pins sampled **eight positions from the displayed windows**, after the first two stepping phases. Do not reuse M-209's lug/drum configuration or fixed once-per-character wheel stepping.

## Exact crank-cycle ordering

The 2023 paper's **Table 4, p. 16**, and explanatory notes on **p. 17**, define the chronology. Clock labels refer to the crank's orientation, not to wall-clock time:

| Crank interval | Action | State handling |
|---|---|---|
| Rest / 6–7 | Read and latch stepping pins at **−5** positions | Capture pre-step snapshot; key depressed |
| 7–10 | Print head aligns to entered character; paper advances | No cryptographic wheel mutation |
| 10–11: phase I | **Only if latched wheel 6 is 1**, each active latched pin of wheels 1–5 moves the wheel **to its right** one position | Apply target-wheel steps **in parallel**, not cascading |
| 11–12: phase II | If wheel 6's original latched pin is 1, **all six wheels advance once** | Uses original latch even if wheel 6 already moved |
| At 1 | Latch cage/PRN pins at **+8**, and freshly latch stepping pins at **−5** | Distinct snapshots; key released |
| Around 2–4 | Cage produces PRN and rotates print head | Uses the latched +8 pins; input is printed |
| 4–5: phase III | Every newly latched active pin on wheel *i* (1–5) steps wheel *i+1* once | **Parallel**; does *not* require wheel 6 to be active |
| At 5 | Output printed | Character complete for encryption |
| 5–6: phase IV | All six wheels advance one position | Final post-character step |
| At 6 | Crank locks | Final wheel state becomes next character's initial state |

**Essential stepping invariants:** wheel 1 does not step in phases I or III; phase II is conditional on the *original* latched wheel-6 bit; phase IV is unconditional. Phase III must use the **new** −5 snapshot, not the snapshot from phase I. Multiple step contributions to a wheel may accumulate across distinct phases. The paper explicitly warns that a wheel-6 movement caused by wheel 5 in phase I must **not** retrospectively alter phase II's decision.

The paper distinguishes the pin-sensing geometries at **−5 for stepping** and **+8 for PRN** (see pp. 11, 15–17). Implement positions with a clearly defined positive step direction and verify with published traces before interpreting offset arithmetic.

## Implementation boundaries and proposed next steps

This is a specification stage; **do not add a Cargo workspace member or crate skeleton yet**.

1. Transcribe and verify Table 5 bit arrays and Table 2 scrambled print rings; add immutable source-backed fixtures.
2. Define typed wheel positions/labels and stepping pin geometries. First test table-driven transitions using all 32 pre-character window tuples; record intermediate per-phase transitions where an independent simulator exposes them.
3. Implement phase I–IV as explicit stages, with separate latched snapshots, and make PRN timing observable to tests.
4. Implement the 25-bar/inversion mechanism with independent PRN fixtures; only then implement print-head encipher/decrypt mapping.
5. Add the canonical shared `old_crypto_rs::Block` façade and text layer when the stateful core is independently verified. Reuse core helpers as appropriate; do not duplicate the trait, grouping utilities, or common permutations.
6. Future integration: Divan benchmarks, demo and TUI, main README; no additions before known-answer tests pass.

Use `thiserror` in `src/error.rs` for any new errors; avoid incompatible public types and duplicating existing core abstractions. Cargo dependencies should use MAJOR.MINOR versions (except `old-crypto-rs` itself, which uses `version = "0"`), as established in the repository.

### Explicitly deferred

- SG-41Z numeric machine: separate design, not reproduced by changing an alphabet constant.
- Manual operating procedures beyond the cipher and conventional text layer.
- Unverified external vectors or guessed rotor stepping conventions.

## Step 3 typed foundations

`src/types.rs` defines checked `WheelId`, `WheelPosition`, `WindowLabel`,
`PinPattern`, and `PinSensor` types. The reference bit strings are interpreted
**only** in Table 5 row order; `PinSensor` records the documented −5 and +8
offsets but does not yet compute sensed bits. `WheelPosition::next_index()`
is a modular index operation, **not a claim about physical wheel stepping**.

The crate's unit tests validate all wheel labels (including the nonuniform
markings of wheel 6), wraparound, pin-string lengths and contents, the 144
source pin settings, and the sensor-offset distinction. Machine state traces,
step timing, and the cipher remain future work.
